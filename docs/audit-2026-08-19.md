# Rill Codebase Audit — 2026-08-19

> **Remediation status (2026-08-19).** Every finding is resolved. The three
> that were initially closed as *assessed, not actioned* were then worked
> through as well, and two of them turned out to be larger than the audit
> knew:
>
> * **P3 (per-frame image uploads)** — the premise did not hold, and the
>   reason it did not was the real finding: **images never rendered at all.**
>   Every renderer passed `NoImageSource`, `rill-vector` discarded the pixels
>   the viewport handed it, and a frame carries an image's source string, so
>   the compositor drew placeholder boxes while the client paid for the fetch
>   and decode. Fixed by giving pixels their own door — `attach_image` on
>   `rill_stream_v1` v2 — and P3 landed with it, since binding an
>   already-uploaded texture is what the transport makes possible.
> * **C6 (rill-history → rill-ui)** — done as the `rill-draw` extraction. The
>   storage crate was compiling a KDL parser, a layout engine, a text shaper
>   and 41 icons to call one `decode()`. Investigating it surfaced a second,
>   worse problem: `specs/history.md` promises transcripts kept indefinitely
>   while frames age out at 90 days, but the transcript was *recomputed from
>   the frames on every query* — so the retention it advertises would have
>   silently destroyed the history it was taken to keep. `Event::Text` (0x04)
>   stores it instead.
> * **Q5, second half (retire `.rillrec`)** — declined, correctly. It is not
>   legacy: the compositor writes it and `--replay` plays it back. It is a
>   tape; `.rhs` is a journal. Its converter called itself a "migration path",
>   which is what invited the inference; both modules now say why there are
>   two.
>
> Also declined, with reasons recorded in `docs/risks.md`: **Q14 (long
> functions)**, which the audit itself found linear and readable, and
> **`missing_docs`**, measured at 730 items that are overwhelmingly struct
> fields inside already-documented variants.
>
> Findings the remediation *added*, none of which the audit had: images never
> rendering and the history retention hole (both above); `rill_doc::compile`
> aborting on deeply nested KDL, since the KDL parser overflows before our
> code runs; the pre-push hook's clippy skipping tests and examples, which is
> why four warnings survived in files it was believed to cover; the fuzz
> lockfile drifting to a `kdl` needing rustc 1.95, so **no fuzz target built
> at all**; `/close` in term-app bypassing the new ownership check until a
> test caught it; and `attach_image` being unreachable at runtime because a
> stream inherits its version from its manager.

**Commit:** `b695c30` (main) · **Scope:** all workspace code (~55k lines Rust across 13 library crates, 4 platform binaries, 7 apps), specs/docs, scripts, workspace manifests.
**Method:** four independent review passes — security, code quality (platform/protocol), code quality (UI/rendering/storage/apps), conventions & architecture — plus `cargo clippy --workspace --all-targets` (4 trivial warnings, all in tests/examples; nothing in production code). Every finding below was verified against the actual source, with file:line citations.

---

## Executive summary

The codebase is in unusually good health for a pre-1.0 solo project. All four passes independently converged on the same characterization: strict, symmetric, capped wire codecs; deny-by-default authorization with no existence oracles; a TOCTOU-safe root jail; bounded buffers whose caps cite recorded measurements; spec↔code fidelity that checked out byte-for-byte everywhere it was sampled; and no crate with zero tests. There is no pre-auth remote code execution, no authorization bypass, and no memory-safety finding.

The findings cluster in four themes:

1. **Two gaps in an otherwise-consistent hostile-input discipline** — unbounded recursion depth in the `.rill` document decoder, and an unescaped-filename injection path in appkit-generated pages. Both are small fixes that close the last aborts/injections reachable from untrusted content.
2. **Process-death paths in long-running binaries** — a transient `accept()` errno exits the server or the whole compositor.
3. **Memory-lifecycle gaps that matter on the 1 GB Pi target** — a handful of maps/caches that grow monotonically, per-frame GPU texture uploads, and a 1 GiB client-side default resource cap.
4. **Workspace/docs hygiene** — release-blocking license state living only in an untracked file, a project plan that still specifies a deleted component, and no `[workspace.dependencies]`/`[workspace.lints]`.

## 1. Security

### High

**S1. No recursion-depth bound in `.rill` document decode — hostile document can abort the viewer via stack overflow.**
The decoder rigorously validates tree shape (`crates/rill-doc/src/codec.rs:898-905`, ref counts at `codec.rs:1174-1181`) but not depth. A chain of ~65k single-child Columns is fully valid under `MAX_NODES` (`crates/rill-doc/src/lib.rs:27`), and consumers recurse once per level (`crates/rill-ui/src/tree.rs:452`, `crates/rill-ui/src/layout.rs:277,414`, `crates/rill-viewport/src/lib.rs:2269`). Stack overflow aborts the whole process — exactly the failure class every other codec cap exists to prevent. **Fix:** one depth check in `decode` (e.g. ≤ 256), computed from the already-available child graph.

**S2. Link/action targets in appkit-generated KDL are not escaped — filenames can break or inject app UI.**
`rill_doc::kdl_escape` is documented as the one correct escaper for *every* interpolated value (`crates/rill-doc/src/lib.rs:73-77`), and labels are escaped everywhere — but targets are not: `file_row`'s `target="{target}"` (`crates/rill-appkit/src/lib.rs:529-537`), `MenuWire::Target` (`lib.rs:517`), `key_link` (`lib.rs:583`). files-app feeds raw filesystem names through these (`apps/files-app/src/main.rs:728-741`, `858-869`, `966-971`). A filename containing `"` 500s the directory listing; a crafted name can inject nodes/verbs into the page (e.g. a row whose "Open" is a delete submit). **Fix:** escape in the appkit builders, or reject non-conforming names at `Entry` construction the way `safe_name` (`main.rs:337`) already does for typed names.

### Medium

**S3. Pack decompression bomb: `decoded_size` is an attacker-set, unbounded decompression cap.**
`crates/rill-pack/src/lib.rs:306` reads `decoded_size` from the index with no ceiling; `Pack::get` (`lib.rs:347`) passes it as the cap to `encoding::decompress`. A malicious pack can declare tens of GB, embed a genuinely-expanding zstd blob, and precompute a matching hash — `Pack::verify` extracts every entry, and app install calls `open + verify` (`crates/rill-app/src/lib.rs:210`), so installing from a hostile server can OOM the client. Fuzzing doesn't cover this (random inputs fail the hash check first). **Fix:** bound `decoded_size` at open against a hard ceiling before any extraction.

**S4. History chunk decompression has no bomb guard.**
`crates/rill-history/src/segment.rs:387` uses `zstd::stream::decode_all` uncapped; `MAX_CHUNK` (8 MiB) bounds only the *compressed* size. Sharing `.rhs` segments is a stated roadmap item, so treat them as foreign. **Fix:** decode via the existing capped helper `rill_store::encoding::decompress` (`crates/rill-store/src/lib.rs:113-130`), as rill-pack already does.

**S5. Terminal escape-sequence CPU amplification.**
`apps/term-app/src/lib.rs:119-141` passes CSI params (up to 65535) unclamped to `scroll_up`/`scroll_down`/`insert_lines`/`delete_lines`, each of which shifts the whole grid per iteration (`apps/term-app/src/screen.rs:149-191`) while holding the screen mutex. One `\x1b[65535L` from `cat`ing a crafted file or a remote host stalls the reader thread. **Fix:** clamp vertical counts to the scrolling-region height (horizontal ops are already bounded by `cols`).

**S6. Terminal sessions are not bound to an identity.**
`apps/term-app/src/lib.rs:557,592` ignore `identity`, and session ids are sequential (`lib.rs:254`) — any device authorized for `/term/**` can read/type into another window's shell. Fine under today's single-user assumption; the kind of assumption that outlives its context. **Fix:** record the opening identity per session and check it, matching files-app's per-device `ui_key` discipline.

### Low

- **S7.** Private key written world-readable then chmod'd, with the chmod result discarded (`platform/rill/src/auth_cmd.rs:86-91`). Create with `OpenOptions` mode `0600` and treat permission failure as an error.
- **S8.** One peer can occupy all 64 connection slots — the semaphore has no per-IP accounting (`platform/rill-server/src/lib.rs:592,625`). Mitigated by the default loopback bind and handshake timeout; revisit before ever binding beyond `127.0.0.1`.

### Observations (no action needed)

- Fingerprint comparisons are not constant-time — correctly so; they compare public cert hashes, not secrets (`crates/rill-auth/src/tls.rs:170`).
- Cert expiry deliberately unenforced under the pinning model; documented and consistent.
- **Fuzz coverage:** protocol frames, doc decode, pack open, stream decode are fuzzed. The `.rhs` segment reader is the natural next target before recording/sharing ships; add a pack seed with a valid-hash oversized `decoded_size` to lock in the S3 fix.

## 2. Reliability & code quality

### High

**Q1. One transient `accept()` error takes down the server — or the entire desktop.**
`platform/rill-server/src/lib.rs:623`: an accept error (`ECONNABORTED`, `EMFILE` under fd pressure) propagates out of `Server::run` and `main.rs:47-50` exits the process. Same pattern in the compositor at `platform/rill-compositor/src/main.rs:2384-2387`, where it kills the desktop and every client on it — inconsistent with the code's own philosophy that "a broken hot-reload must never take the desktop down" (`main.rs:1470`). **Fix:** log-and-continue on retriable errnos, with a short sleep for fd exhaustion. Highest-value single-line class of fix in the audit.

### Medium

**Q2. Compositor per-surface maps grow without bound over a long session.**
Four `HashMap<ObjectId, …>` fields never shed entries for closed windows: `spawn_times` (`platform/rill-compositor/src/main.rs:323`, inserted :3279), `prev_window_pos` (:300), `window_velocity` (:305), and `record_ids` (:342 — removed only via the rill_stream destroy path; foreign buffer-backed windows leak forever). The code already culls `widgets` post-`space.refresh()` for exactly this reason (:2392-2394). **Fix:** prune all four in the same cull.

**Q3. Clipboard paste can freeze the vector client indefinitely.**
`platform/rill-vector/src/main.rs:1626-1648` does a blocking `read_to_end` on the data-offer pipe from the single-threaded event loop; `take(MAX_PASTE)` bounds size but not time — a source that never closes the pipe hangs the window. **Fix:** poll-with-timeout (the loop already uses `libc::poll` at :1270) or `O_NONBLOCK`.

**Q4. `handle_connection` duplicates its security-relevant paths.**
The fatal request-id block is copy-pasted (`platform/rill-server/src/lib.rs:838-850` vs :920-929), the deny-as-NOT_FOUND logic exists twice (:854-861 vs :989-994), and the byte-identical "not found" property the loopback test asserts is protected only by discipline, not structure. Also `policy.authorize` runs twice per static-path request (:937, :989). **Fix:** single verb dispatch with one fatal-id helper.

**Q5. Duplicated command-transform logic; two parallel recording codecs.**
`rill_ui::stream::scale_commands` (`crates/rill-ui/src/stream.rs:993-1114`) and rill-viewport's private `scale_command` (`crates/rill-viewport/src/lib.rs:2022-2097`) are hand-maintained copies with their own clamp rules; they agree today, nothing enforces it. Likewise `.rillrec` (`crates/rill-ui/src/recording.rs`) vs `.rhs` (`crates/rill-history/src/event.rs`) — `examples/convert-rillrec.rs` suggests the former is legacy. **Fix:** deduplicate the scaler; deprecate or delete `.rillrec`.

**Q6. Error page recompiled every frame.**
`crates/rill-viewport/src/lib.rs:790-812`: with `tree == None`, every layout call runs the full KDL→encode→decode pipeline. Build the error tree once in `apply_load`.

### Low

- **Q7.** Client request-id `u32` counter has no wrap handling (`crates/rill-client/src/lib.rs:577-579`) — debug panic / release wrap-to-reserved-0 after ~4B requests. Make it a deliberate `ClientError::Dead`.
- **Q8.** Multi-chunk dynamic responses copy the whole payload a second time (`platform/rill-server/src/lib.rs:1119-1127`); use `split_off`/`drain`.
- **Q9.** `rill auth trust` probe has no connect/handshake timeout (`platform/rill/src/auth_cmd.rs:283-291`), unlike the normal client path.
- **Q10.** Dock reaps exited app children only on next launch (`platform/rill-vector/src/dock.rs:262`); zombies linger. Add a `try_wait` sweep in `tick`.
- **Q11.** `draw()` in rill-vector uses `expect` on encode/memfd (`platform/rill-vector/src/main.rs:694-697`) — fd/memory pressure kills the launcher instead of skipping a frame; seal `fcntl` result ignored (:241-247).
- **Q12.** `Corpus::tail` uses `continue` where `break` is meant (`crates/rill-history/src/corpus.rs:195`) — keeps scanning all remaining segments after `n` is satisfied.
- **Q13.** `caret_at_click` is O(n²) in line length (`crates/rill-viewport/src/lib.rs:2210-2217`; same pattern `crates/rill-ui/src/layout.rs:1124-1146`). Fine for fields, will hurt in multiline editors.
- **Q14.** Very long functions: studio-app `page()` ~825 lines (`apps/studio-app/src/lib.rs:879-1703`), files-app `directory_page` ~345 lines, `Renderer::with_device` ~850 lines. Linear and readable, but `page()` deserves extraction.
- **Q15.** App boilerplate an appkit should own: `field()` duplicated verbatim (files-app `main.rs:327`, notes-app `main.rs:196`); the `RILL_TRACE`/`RILL_DUMP_KDL` traced-compile helper exists in only 2 of 7 apps, so the trace tooling silently doesn't work in the other five.

## 3. Memory & performance on the 1 GB target

**P1 (medium). Client `max_resource` default is 1 GiB — on a 1 GB machine.**
`crates/rill-client/src/lib.rs:164`, enforced at :448/:455; no caller overrides it. The OOM killer arrives long before the cap. Documents are "kilobytes over the wire" by design — a tens-of-MiB default with opt-up for downloads matches the threat model.

**P2 (medium). `AppView.images` grows without bound for the life of a view.**
`crates/rill-viewport/src/lib.rs:206`, populated in `request_images` (:634-646), never evicted — decoded RGBA for every page ever visited accumulates. Evict entries not referenced by the current tree after `apply_load` (the tree walk already exists).

**P3 (medium). rill-gpu re-creates GPU resources per frame.**
`upload_image` creates a fresh texture + full upload + bind group for every Image command on every built frame (`crates/rill-gpu/src/lib.rs:3705-3751`, honestly flagged "P3" in a comment); `build_frame` allocates fresh instance/uniform/mask buffers (:2673-2772); `blur_chain` allocates per Kawase pass (:3615-3638). For wallpaper-sized images this is the largest avoidable cost in the crate. The existing `FxCache` (:3545-3601) is the pattern to extend.

**P4 (low). `StreamFrame.raw` pins every window's full encoded frame permanently** (`platform/rill-compositor/src/main.rs:353-362`) — with `MAX_STREAM_SIZE` = 4 MiB, a hostile client can pin ~8 MiB/surface. Keep `raw` only while recording or the HUD is up.

**P5 (low). Shaper cache is entry-bounded, not byte-bounded** (`crates/rill-gpu/src/text.rs:299`): 4096 entries × up-to-64 KiB keys ≈ 256 MB worst case, and the clear-at-cap causes re-shape storms instead of LRU eviction.

## 4. Conventions, workspace & docs

### High

**C1. `CREDITS.md` — release-blocking license state — exists only in the working tree.**
Untracked at repo root. It records that `assets/shaders/grass_sunset.wgsl` adapts a **CC BY-NC-SA 3.0** Shadertoy work (incompatible with `MIT OR Apache-2.0`; three more shaders flagged for verification) plus the 2026-08-19 disposition. A hard reset or fresh clone erases it. **Fix:** commit it today.

**C2. `proj-plan.md` still specifies the deleted `rill-shell` as current architecture.**
`TODO.md:622` records its deletion, and the compositor's manifest references "since the gpui shell retired" — yet `proj-plan.md` line 16 puts `rill-shell` in the stack diagram and lines 1053-1060, 1211, 1272, 1316, 1396, 1458, 1519 assign it responsibilities now split between the compositor and `rill-vector --dock`. Given risks.md item 11 (an engineer going spec→feature without a walkthrough), this is the most misleading document in the repo. **Fix:** one retirement paragraph pointing at TODO.md:622, plus diagram edit.

### Medium

- **C3.** No `[workspace.dependencies]` — versions duplicated across 17 manifests (`toml` 8×, `tokio` 6× each with its own feature list, `libc` 4×, `wgpu` 2×…). They agree today by hand discipline alone. No first-party skew in `cargo tree --duplicates` yet. ~An hour of mechanical work removes the class.
- **C4.** `crates/rill-appkit/Cargo.toml` opted out of workspace inheritance and is the **only crate with no `license` field** (and no description). Three-line fix.
- **C5.** No `[workspace.lints]`; the quality gate is an opt-in local pre-push hook whose lines 18-60 hardcode one machine's openSUSE library shim — a Debian/Arch contributor gets silently created shims. Gate the shim on hostname or move it to an opt-in script.
- **C6.** Layering inversion: `rill-history` (durable storage format) depends on `rill-ui` (presentation) to decode frame blobs at seal time. If `.rhs` is meant to outlive UI churn (specs/history.md's premise), the frame-decode seam belongs in a leaf crate both can share.

### Low

- `.gitignore` comments reference pre-rename paths (`examples/showcase/`).
- No `rust-version` in `[workspace.package]` — edition-2024 failures on old toolchains will be confusing instead of a clear MSRV message.
- App manifest inconsistencies: descriptions on 2 of 7 apps; redundant `[lib] path`; stray empty `[dev-dependencies]` in studio-app; the lib-vs-bin split in `apps/` is inferable but undocumented in `apps/README.md`.
- Logging is bare-eprintln-by-convention (zero `tracing`/`log` in the workspace; the server hand-rolls a structured stderr logger at `platform/rill-server/src/lib.rs:107-109`). Internally consistent, but nothing records it as a decision — and the enterprise agent-governance direction will eventually want real telemetry.
- `missing_docs` unenforced; all 13 `lib.rs` files open with spec-citing `//!` docs (good) but trivial public items go bare.
- Clippy: 4 trivial warnings, all tests/examples (`crates/rill-store/src/lib.rs:535`, `crates/rill-ui/examples/history-spike.rs:163`, `crates/rill-ui/tests/layout.rs:1234` — a harmless `true && false` literal in a fixture, verified not a vacuous assertion — `crates/rill-viewport/src/lib.rs:2222`).

### Verified — no drift found

Spec↔code sampling all matched exactly: protocol frame layout, flags, status codes, and every §9 limit (`specs/protocol.md` vs `crates/rill-protocol`); document node table including canary type-ids (`specs/document-format.md` vs `crates/rill-doc`); TLS 1.3-only, ALPN `rill/1`, deny-only policy, anonymous-vs-device identity (`specs/security.md` vs `crates/rill-auth`). Tier boundary is clean: `crates/*` depend only on `crates/*`; apps-depending-on-server-lib is the documented application model; the one compositor→viewport back-edge is dev-only and documented as a drift tripwire. The two `stream_protocol.rs` files are wayland-scanner-generated from the single shared XML — no drift risk.

## Strengths

- **TOCTOU-safe root jail**: open first, verify the fd's real path via `/proc/self/fd`, fail closed on non-canonical roots — with tests pinning it (`platform/rill-server/src/lib.rs:1141-1189`).
- **No-oracle authorization**: denial ≡ absence, handler statuses clamped, unauthorized GET_IF never confirms a hash — each property has a loopback test.
- **Codec discipline everywhere**: strict decode, self-verifying encode, checked arithmetic, per-field caps, allocation only after validation, truncation-at-every-byte tests, committed fuzz corpora with seed-writer tests.
- **Measured engineering**: caps and budgets cite recorded measurements (the 225 MiB cache leak, 7.25 ms phantom composites, zstd ratios); comments record the failure each design replaced.
- **Bounded-by-default with the bound explained**: HashMemo LRU with eviction test, fixed-size FrameTimes histogram with a memory test, slowloris two-budget read, recorder error-latching.
- **Test coverage where it matters**: 1,033 lines of real-TLS loopback tests covering the auth matrix and decompression bombs; codec golden vectors; files-app pins policy-is-the-UI; term-app drives a real shell; no crate has zero tests.
- **Traceability**: every `lib.rs` opens by citing its governing spec; manifest dependency comments explain *why*; TODO.md is a live, honest audit log; rustfmt non-adoption is a documented decision, not neglect.
